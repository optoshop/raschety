# Правила обновления цен WP (четырёхклапанные) из manager-6

Источник расчёта: [raschet-op / manager-6](https://raschet-op.vercel.app/manager-6)  
Логика в JS: `/plugins/raschet-op/assets/raschet-op-6.js` (CFG на странице: `vat=0.2`, `tax=0.2`, `limit=300` м², листы БМ).  
Скрипт: `scripts/update_shop_prices_manager6.py`.

База для обновления: исходный `shop_27.10.csv` (не предыдущий `*-updated`).

---

## Что трогаем / не трогаем

| Действие | Правило |
|----------|---------|
| **Меняем** | Только категория **«Четырехклапанные коробки»** и её вариации (`regular_price`). |
| **Не меняем** | Самосборные, крышка-дно, гофротара, МП-упаковка и любые другие категории. |
| **Не меняем** | `tax:product_cat`, `tax:product_tag` и прочий контент. |
| **Sale** | **Не трогать совсем**: товары с заполненным `sale_price` (родитель или вариация) — ни `regular_price`, ни `sale_price`. |
| **Исключить из логики** | SKU **K1034**, **K59–K65** (не обновлять, не добавлять). |
| **Не рассчитывается** | Если калькулятор пишет «только штанцформа» (`!canBM && !canU`) — **цены не менять**. Пример: 72×72×90. |
| **Исключение 600×400×400** | SKU вроде K1020/K1021/K1022 (и любой товар с размером 600×400×400) — **оставить цены как на сайте** (в CSV-базе). Калькулятор формально считает БМ, но по бизнес-правилу не применяем. |

## БМ vs У (кто даёт цену продажи)

Возможность производства в manager-6 (размеры Д×Ш×В из названия, мм):

```text
canU  = L ≥ 125 && W ≥ 125 && H ≥ 63
canBM = L ≥ 240 && W ≥ 80  && H ≥ 80 && (W + H) ≥ 280
```

Выбор ряда цен:

1. Если **canBM** → брать строку **«Продажа БМ»**.
2. Иначе если **canU** → брать **«Продажа У»**.
3. Иначе → штанцформа, цены не менять.

Поставщики в Excel (У / БМ / другие) для этой выгрузки **не переопределяют** выбор: ориентир — возможность в калькуляторе.

## Маппинг тиров WP ↔ колонки калькулятора

В manager-6 сводная таблица по умолчанию: qty **50 / 100 / 300 / 500 / 1000**.

| `meta:attribute_pa_colichestvo` | qty в калькуляторе |
|---------------------------------|--------------------|
| `50-90 шт` | 50 |
| `100-290 шт` | 100 |
| `300-490 шт` | 300 |
| `500-990 шт` | 500 |
| `1000+ шт` | 1000 |

В `regular_price` вариации пишется значение **«Продажа …» с НДС** (как `toFixed(2)` при включённом НДС: цена без НДС × 1.2).

### Текст тиров в `post_excerpt`

У родителей, чьи `regular_price` вариаций реально обновили, в коротком описании пересобираются строки тиров:

```text
<strong>50-90 шт — 2,51 руб с НДС</strong>
…
<strong>1000 + шт — 1,84 руб с НДС</strong>
```

- цены = актуальные `regular_price` вариаций;
- десятичная **запятая**;
- тире **—**;
- суффикс **`руб с НДС`**;
- подпись `1000 + шт` (с пробелами), как в карточке на сайте.

Sale и товары без смены цен — текст `post_excerpt` **не менять**.

## Как считается «Продажа БМ» / «Продажа У» (кратко)

Площадь заготовки: `(2×(Д+Ш)+60) × (Ш+В+8) / 1e6` м².

- **У:** закуп/шт = площадь × `baseCost(1)` × `prodU(1.73)`; продажа = закуп × (коэф. кол-ва У × коэф. площади У); затем ×1.2 НДС.
- **БМ:** себестоимость заказа через раскладку на листы (с обрезками при полезной площади заказа ≤ 300 м²), на тир; продажа = (выручка/шт) × (коэф. кол-ва БМ × коэф. площади БМ); затем ×1.2 НДС.

Коэффициенты по умолчанию — как в UI manager-6 (зашиты в скрипт).

## Запуск генерации

```bash
python3 scripts/update_shop_prices_manager6.py \
  --shop-in shop_27.10.csv \
  --shop-out shop_27.10-updated.csv \
  --stats-out /tmp/manager6-price-stats.json
```

Итоговый файл для импорта в WP: **`shop_27.10-updated.csv`** в корне репозитория (копия также в Project store `docs/shop_27.10-updated.csv`).  
Категории/теги (`category-2`, `tag-2`) этим скриптом **не меняются**.

## Excel «1. Коробки Закуп + ОПТ» → лист Calc

Скрипт: `scripts/update_calc_prices_from_shop.py`.

1. На листе **Calc**, колонка **K** («Продажа коробка с НДС») — подставить новые цены из `shop_*-updated.csv` для SKU, у которых на сайте реально меняли `regular_price` (тиры I=50/100/300/500/1000 → те же 5 вариаций).
2. Старое значение K → колонка **AE**, **только если цена изменилась**; если K уже совпадает с shop — AE не трогать.
3. Обновлённые ячейки K — **зелёный фон** (`92D050`).
4. Sale / нетронутые SKU / другие листы — без изменений.
5. Результат: **`1. Коробки  Закуп + ОПТ-updated.xlsx`** (исходник не перезаписываем).
